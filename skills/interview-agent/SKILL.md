# Interview Agent

## 任务路由

开始执行前，先识别用户本次明确要求的任务，并按用户表述顺序完成。不要自行增加任务。

- 用户说“开始”“处理最新面试”或明确要求转写并复盘：运行完整流水线。
- 用户要求把某场已有复盘的摘要发送或推送到飞书：进入仅发送摘要模式，只读取现有复盘并发送，不转写、不重新复盘、不修改复盘文件。
- 用户要求“补充复盘”并给出具体重点：进入补充复盘模式，只更新指定复盘的相关章节。
- 一条请求包含多个明确任务时，依次完成全部明确任务；完成后停止。

仅发送摘要模式下，如果找不到目标复盘文件，直接报告缺失并停止，不得自动转写或生成复盘。

## 目标

把一次面试处理为完整流水线：

```text
最新未处理录音
→ 本地 FunASR 转写
→ <配置的 Inbox>/<base>_speakers.txt
→ 直接生成结构化 Markdown 复盘
→ <配置的 Reviews>/<base>.md
→ 可选：向配置的飞书群发送完成提醒与关注重点
```

这是 `interview-transcribe` 和 `interview-review` 的总控入口。已安装这两个 Skill 时，读取并遵守它们的完整规则；不能直接加载时，仍按本 Skill 规定的阶段、路径、验证和安全边界执行，不要求用户重复粘贴提示词。

## 极简调用

用户只说“开始”时，直接运行整条链路，不询问文件名：

1. 扫描面试录音目录中的音频。
2. 找出尚无对应转写结果的最新录音。
3. 只有一个可靠候选时直接处理。
4. 仅当多个候选文件修改时间接近、无法可靠判断时，列出简短文件名让用户选择。

用户指定文件名或路径时，优先处理该文件。

## 阶段一：选择录音

支持常见音频格式：`.m4a`、`.mp3`、`.wav`、`.aac`、`.flac`、`.mp4`。

按修改时间从新到旧检查，以 `<音频主干>_speakers.txt` 为预期转写结果，优先选择配置的 Inbox 中尚无对应结果的最新音频。

如果最新录音已经有转写、但尚无复盘，可以跳过转写，直接对现有转写执行阶段三。不得为了完整走流程而重复转写。

## 阶段二：转写

使用 `INTERVIEW_TRANSCRIBE_SCRIPT` 指向的本地脚本和 FunASR。未配置时，才查找此前成功使用、并包含说话人分离和热词配置的脚本。

调用形式按脚本实际接口选择：

```text
python3 1_transcribe.py <音频路径> <输出路径>
```

或：

```text
python3 1_transcribe.py <音频路径>
```

输出必须写入：

```text
<配置的 Inbox>/<base>_speakers.txt
```

要求：

- 保留完整内容、时间顺序与说话人标签。
- 使用脚本已有的模型级热词和文本级纠错配置。
- 不修改脚本、热词表或原始录音。
- 不覆盖已有转写；发生重名时追加 `-2`、`-3`。

转写结束后必须验证输出文件存在、非空且包含说话人标注。验证失败时立即停止，不进入复盘阶段，并在当前对话说明失败环节和可操作的下一步。不得声称复盘已经完成。

## 阶段三：复盘

完整读取刚生成或选定的 `*_speakers.txt`，不得只读局部。

在内部完成问答拆分与分析后，直接生成最终 Markdown。Markdown 至少包含：

- 基础信息：公司、岗位、轮次、日期、源文件。
- 问题清单。
- 逐题复盘：原问题、原回答、追问、考察点、亮点、具体问题、更好的结构、推荐回答、待补充信息、标签。
- 知识盲区。
- 表达问题。
- 后续准备。
- 整体复盘。

事实只能来自文件名或转写内容。不得虚构项目数据、经历或公司内部信息；缺失的关键信息标记为 `[待补充：……]`。

最终写入：

```text
<配置的 Reviews>/<base>.md
```

其中 `base` 是去掉 `_speakers.txt` 的文件名。不得覆盖已有文件；重复生成时依次使用 `<base>-2.md`、`<base>-3.md`。

Markdown 必须包含：

1. 基础信息。
2. 问题清单。
3. 逐题复盘。
4. 知识盲区。
5. 表达问题。
6. 后续准备。
7. 整体复盘。

写入后验证复盘文件存在、非空且包含上述主要章节。验证失败时不得发送“已完成”。

## 阶段四：发送飞书群提醒

仅当转写（或已有有效转写）和复盘写入均验证成功后，且用户配置了飞书/Lark 目标群时，发送一条简洁提醒，并在当前对话报告发送结果。未配置通知渠道时，完成本地复盘后正常结束。

使用本 Skill 自带的 `scripts/send_feishu_summary.py`，将完整 Markdown 摘要通过标准输入交给脚本。不得现场拼接包含消息正文的 Shell 命令，也不得直接调用存在参数拆分问题的 shim。

调用形式：

```text
python3 <skill目录>/scripts/send_feishu_summary.py --interview-id <base> --chat-name <配置的群名>
```

把摘要内容通过执行工具的标准输入传入。如果执行工具不能直接写入标准输入，可以把摘要写入本次运行专用的临时文件，再使用输入重定向 `< 临时文件`；消息正文不得通过命令替换、变量展开或命令行参数传递。发送结束后只删除这个由本次运行创建的临时文件。

目标群配置按以下优先级解析：

1. 本地环境变量 `INTERVIEW_AGENT_FEISHU_CHAT_ID`。
2. 调用时明确提供的群 ID。
3. 环境变量 `INTERVIEW_AGENT_FEISHU_CHAT_NAME` 或用户明确提供的群名，并要求精确匹配。

Skill 包中不得写入真实群 ID、账号、密钥、用户名或机器绝对路径。公开分享后，每位使用者自行配置目标群。

脚本会自动识别千问 Work 的核心飞书 CLI；在其他环境中解析标准 `lark-cli` 的真实程序。消息使用参数数组传递，并自动生成幂等键，避免 Shell 引号拆分和短时间重复发送。

自动通知默认使用机器人身份发送，且机器人必须已经加入目标群。不得在机器人不可用时静默改为用户身份发送。

使用 Markdown 富文本发送，并为同一场面试使用稳定的幂等键，避免短时间重试产生重复通知。消息内容不得包含完整逐字稿或敏感原文，只包含复盘定位信息、重点问题和下一步动作。

提醒格式：

```text
面试复盘已完成，并已写入 Obsidian。

面试：<公司>-<岗位>-<轮次>-<日期>
interview_id：<base>
复盘文件：<配置的 Reviews>/<实际文件名>

本次建议重点关注：
1. <最高优先级的具体问题>
2. <第二优先级的具体问题>
3. <最值得补齐的知识或数据>

下次面试前优先准备：<一个最重要、可执行的动作>

如有遗漏，请回复本消息：
补充复盘：<你认为需要重点分析的内容>
```

关注重点必须来自本次复盘，优先选择：

- 重复出现或明显导致追问的问题。
- 指标定义、数据口径或事实依据缺失。
- 没有回答问题本身、逻辑跳跃或案例支撑不足。
- 推荐回答中标记为待补充的信息。
- 对下一场面试影响最大的知识盲区。

最多列 3 项，使用具体、可执行的表达，不写“更加结构化”“继续加油”等泛泛建议。

飞书发送失败不改变复盘文件已经成功写入的事实。此时在当前对话明确报告“复盘已完成，但飞书通知失败”，并给出失败原因；最多自动重试一次，不得因为通知失败重复生成复盘。

发送成功后：如果本次请求没有其他尚未完成的明确任务，立即结束；如果用户在同一请求中明确要求了其他任务，继续执行这些任务后结束。

## 阶段五：处理飞书反馈

当本 Skill 因配置的飞书群消息被调用，并且消息以 `补充复盘：` 开头时，执行反馈更新流程：

1. 优先从被回复的通知消息中读取 `interview_id` 和复盘路径；不得仅凭当前日期猜测目标面试。
2. 重新读取 Obsidian 中的最新复盘文件，不使用旧对话缓存覆盖文件。
3. 在对应题目或最相关章节中局部补充分析、改进建议和推荐回答；保留其他已有内容。
4. 如果反馈无法对应到现有题目，新建清晰的“补充重点复盘”小节，并注明它来自用户反馈。
5. 如果目标面试或修改位置仍不明确，先在原飞书消息下提问，不得修改文件。
6. 写入前再次确认文件没有被其他 Agent 更新；如已变化，重新读取并合并。
7. 更新成功后回复原消息，说明修改了哪个文件、哪个问题或章节，以及新增了什么。

普通讨论消息、没有 `补充复盘：` 前缀的消息以及其他 Agent 的状态消息，不得自动修改 Obsidian。

本 Skill 本身不会在后台常驻监听飞书。自动接收新回复依赖千问已经启用的飞书事件监听或自动化；如果环境只能发送消息，则用户需要在千问中转述该反馈后再执行本流程。

## 状态与重试

- 已有有效转写但没有复盘：只运行复盘。
- 已有转写和复盘：默认选择下一个未处理录音；没有未处理项时报告“当前没有待处理面试”，不要重复生成。
- 转写失败：停止并报告，不生成复盘。
- 复盘失败：保留已生成的转写，报告失败；下次“开始”从复盘阶段继续，不重复转写。
- 同一阶段最多自动重试一次；再次失败后停止，避免无限循环。

## 边界

不得：

- 修改、移动或删除原始录音和转写稿。
- 覆盖已有文件。
- 自动更新问题库、项目案例库、知识库或长期 Memory。
- 在复盘未实际写入成功时发送成功提醒。
- 在飞书 CLI 未返回成功结果时声称通知已发送。
- 向微信、短信或未指定的其他渠道发送消息。
- 因群内普通聊天内容自动修改 Obsidian。
- 读取、整理、压缩、合并、清理或更新任何 Memory。
- 因 Memory 已满而执行腾挪、合并或删除操作。
- 执行用户没有明确要求的维护任务。

清理规则：只允许删除当前这次运行由本 Skill 自己创建的临时消息文件。不得删除、移动或修改其他临时文件、录音、转写、复盘或缓存。`scripts/send_feishu_summary.py` 默认通过标准输入传递内容，不创建临时消息文件。

完成任务后，除完成提醒外，不要求用户再次运行 `interview-review`。
