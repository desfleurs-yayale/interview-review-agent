# Interview Transcribe

## 极简调用

用户只说“开始”或没有提供音频文件名时：

1. 扫描面试录音目录中的支持格式音频，按修改时间从新到旧排列。常见格式包括 `.m4a`、`.mp3`、`.wav`、`.aac`、`.flac` 和 `.mp4`。
2. 对每个音频计算预期结果名 `<音频文件主干>_speakers.txt`。
3. 优先选择配置的 Inbox 中尚无对应结果的最新音频。
4. 如果只有一个符合条件的候选文件，直接转写，不再要求用户补充路径、命名或热词规则。
5. 只有多个候选文件修改时间接近、且无法可靠判断用户意图时，才列出简短候选文件名请用户选择。

用户提供文件名或路径时，直接处理指定音频。不得要求用户重复输入输出目录、输出格式或防覆盖规则。

## 执行环境

真正的转写由 `INTERVIEW_TRANSCRIBE_SCRIPT` 指向的本地脚本和 FunASR 完成；本 Skill 负责选择输入、调用脚本、检查结果和报告路径，不假装自行完成 ASR。

优先读取 `INTERVIEW_TRANSCRIBE_SCRIPT`。未配置时，才在已知项目目录或当前工作区中查找 `1_transcribe.py`。如果存在多个脚本，优先使用此前成功运行、且包含说话人分离与热词配置的版本；无法判断时再询问用户。

调用方式：

```text
python3 1_transcribe.py <音频路径> <输出路径>
```

如果脚本只要求输入参数，可使用：

```text
python3 1_transcribe.py <音频路径>
```

但必须确认最终结果被写入 `面试/inbox/`；如脚本默认写到其他位置，应使用它支持的输出参数指定正确路径，不要擅自修改脚本。

## 输入与输出

- 输入：面试录音目录中的音频，或用户明确指定的音频文件。
- 输出目录：由 `OBSIDIAN_VAULT` 与 `INTERVIEW_INBOX_RELATIVE` 组合得到，建议默认值为 `Interview/Inbox/`。
- 输出文件：`<音频文件主干>_speakers.txt`。

例如：

- 输入：`某公司-产品岗-一面-2026-01-01.m4a`
- 输出：`Interview/Inbox/某公司-产品岗-一面-2026-01-01_speakers.txt`

若音频主干已经以 `_speakers` 结尾，不要重复追加。

如果目标文件已存在，不得覆盖。依次生成 `<主干>_speakers-2.txt`、`<主干>_speakers-3.txt`，继续递增直到找到不存在的文件名。若本地脚本已有同等防覆盖机制，优先使用并核对实际输出路径。

## 转写要求

- 保留完整内容与原始时间顺序。
- 启用脚本已有的说话人分离能力，保留说话人标签。
- 使用脚本已有的模型级热词和文本级纠错配置。
- 保留或报告 `postprocess_hotword_matches` 等纠错命中明细（若脚本支持），便于检查误替换。
- 不因语句不通顺而自行改写转写事实。
- 不把不确定的人名、公司名或专业术语强行改成确定内容。

## 边界

只负责音频转写并生成新的 `_speakers.txt`。不得：

- 分析或复盘面试内容。
- 自动生成面试复盘 Markdown。
- 修改、移动或删除原始录音。
- 覆盖已有转写结果。
- 自动更新问题库、项目案例库、知识库或 Memory。
- 未经用户要求修改 `1_transcribe.py`、热词表或 FunASR 配置。

## 完成检查

结束前确认：

- 本地转写进程成功结束。
- 实际输出文件存在且非空。
- 内容包含说话人标注；若缺失，明确报告，不得声称成功完成说话人分离。
- 输出位于配置的 Inbox，没有覆盖已有文件。

完成后只需简洁报告本次音频路径、实际生成的转写文件路径，以及是否存在需要人工检查的热词替换或说话人标注异常。
